## Implemented input boundary

- `InputRouter` is renderer-free and owns held keys, one active pointer gesture,
  normalized pointer steering, and one pending Pulse edge.
- WASD and arrows steer. Space emits one Pulse only when `repeat` is false.
- Mouse hover follows. Mouse down is a click candidate until movement exceeds
  14px; a drag then becomes Steer-only and its pointer ID cannot Pulse.
- Touch starts in one immutable role. Left 70% is Steer-only; right 30% is a
  Pulse candidate. Moving a right-zone pointer more than 14px cancels it rather
  than rerouting it. A click/tap must finish within 350ms.
- Only one pointer is admitted at a time. Secondary IDs, duplicate up events,
  cancelled gestures, and long/drifted taps cannot create a Pulse.
- Opening settings, `pointercancel`, window blur, document visibility change,
  and restart clear held keys, pointer ownership, and unconsumed Pulse.
- Cooldown input still reaches the deterministic simulation, so it produces
  `pulse-cooldown` feedback but no TwinkleSeed.
- Control hints become learned only after `gate-pass` and `node-perfect` or
  `node-good`, not after raw movement or an invalid Pulse attempt.
