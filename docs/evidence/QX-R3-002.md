## Implemented gameplay boundary

- `RailFlightState` extends the renderer-free Journey state with integer-mm
  distance, forward speed, corridor offset, score, Life Chain, Flow Purity,
  mistakes, assist state, cooldown/slowdown, active encounter, one-shot result
  IDs, and an immutable GameplayEvent ledger.
- Story time still owns the exact 180-second six-phase journey. Gate, obstacle,
  and node results use rail distance plus the two corridor axes.
- Gates resolve once as pass or miss. Obstacles resolve once as hit, near miss,
  or silent clear using full 3D endpoint separation. A hit slows forward motion
  for 650ms and then recovers.
- Fractional millimetres carry across simulation slices, so canonical integer
  `distanceMm` does not change when one second is partitioned into 60 steps.
- Requested intervals are internally partitioned onto the canonical 60Hz clock;
  slowdown expiry is integrated piecewise inside the final slowed slice.
- A pulse starts an exact 700ms journey-time cooldown without per-slice integer
  rounding. A valid node pulse at 690ms is rejected and one at 700ms is accepted.
  Only a Life Node within its 3D good radius creates a TwinkleSeed; empty space
  and cooldown attempts create no Seed.
- Three consecutive misses raise assist and widen only the next Gate by 50%.
  There is no game-over path.
- Normal play no longer synthesizes an Answer at 168.5s. A valid node Pulse in
  ANSWER may set `answerAt`; opt-in auto-give waits for a nearby Life Node.
- The authored story clock now uses the same integer-ms boundary interpretation
  as the v2 WorldPlan, closing the 3-second long-run renderer mismatch found by
  the Graybox recorder.

The temporary default encounter list exists only for R3 graybox validation.
QX-R3-004 must replace it with deterministic WorldPlan-generated encounters;
this task does not claim final level composition or visuals.
